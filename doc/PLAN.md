# 实施路线

项目按需求分析、工具链验证、模型、命令、CLI、文件读写和回归检查逐步实现。M0–M6 已完成，各阶段对应仓库中的分步提交。

| 阶段 | 主要内容 | 验证重点 |
| --- | --- | --- |
| M0 需求与架构 | 保存原始需求，划分模块与依赖，确定 Command、Composite 和两处分派 | 明确 Phase 1 范围、变化点与验收依据 |
| M1 工具链与实验 | TypeScript strict、项目内依赖与锁文件、Node 测试运行器；XML 与矩阵实验 | 编译和类型检查；文本、嵌套顺序、变换与错误处理 |
| M2 图形树模型 | 六种图形、SvgDocument、id 索引、有序父子关系与深拷贝快照 | 多态操作、树不变量、循环拒绝、换父级补偿与快照恢复 |
| M3 编辑与历史 | 全部编辑命令、EditCommand、CommandHistory、EditorSession | 一条命令一次撤销；失败原子性、redo 分支与 I/O 屏障 |
| M4 CLI | Tokenizer、CommandDispatcher、REPL、tree/show/help 与统一错误输出 | 引号、颜色、in 尾缀、脚本输入、错误后继续与 EOF |
| M5 SVG 文件读写 | read/save/init/canvas、SVG 编解码、自动 id 与原子文件替换 | 完整会话回放、文件往返、不支持内容报错、失败保留状态 |
| M6 回归与架构复核 | 边界测试、浏览器与 PTY 检查、独立检出复现、架构图和报告 | 55 项测试、43 个源文件架构检查、示例与已知限制 |

## 关键实施顺序

1. **先验证变换方案。** XML 和矩阵实验确认嵌套变换对文字、描边和样式的影响，再确定保留仿射矩阵的模型。
2. **先保证模型不变量。** id、父子关系、兄弟顺序与换父级规则集中在模型层，CLI 只解析输入和展示结果。
3. **先在内存中验证历史。** 编辑在副本文档中执行，成功后提交；通过存储端口替身检查 I/O 屏障，再接入真实文件系统。
4. **逐层验证输入到输出。** 从领域测试推进到命令、真实 CLI、文件读写和浏览器预览，最后在独立检出中复现安装与运行。

## 主要修订

- SvgCodec 通过 ShapeReader 端口构造模型；ShapeInput 从 factories 移到 ports，使依赖符合模块边界。
- 换父级采用相对公共祖先的矩阵，避免共享奇异祖先导致不必要的求逆失败。
- XML 增加字符校验、严格序列化和 CR 引用，保证导出的文本可被标准 XML 解析器读取。
- undo 的成功反馈改为显示恢复后的属性、父级和顺序。
- 测试目录补充 cli 与 support，开发工具集中在 scripts。
